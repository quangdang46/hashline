## hashline vs sed (str-replace) comparison

> hashline adds content-hash safety (stale anchor detection, atomic transactions)
> at comparable raw speed to sed. sed is a pure text-stream tool with no safety checks.

### Single-line edit by line number

| Tool | File | Mean | Range |
|------|------|-----:|------:|
| hashline edit | small.rs (100 L) | 0.8 ms | 0.7–1.0 ms |
| sed -i | small.rs (100 L) | 0.7 ms | 0.5–0.9 ms |
| hashline edit | medium.rs (10k L) | 1.5 ms | 1.3–1.7 ms |
| sed -i | medium.rs (10k L) | 1.2 ms | 1.2–1.4 ms |
| hashline edit | large.rs (100k L) | 9.1 ms | 8.7–9.2 ms |
| sed -i | large.rs (100k L) | 6.6 ms | 6.5–6.7 ms |

### Content-based replacement (100k lines)

| Tool | Operation | Mean | Range |
|------|-----------|-----:|------:|
| sed 's/…/…/' | content match replace | 10.2 ms | 10.0–10.7 ms |
| hashline edit | anchor-based replace | 9.0 ms | 8.7–9.5 ms |

> **hashline is faster** for content-based replacement because sed scans every line
> with regex matching, while hashline jumps directly to the anchor.

### Multi-line operations (100k lines)

| Tool | Operation | Mean | Range |
|------|-----------|-----:|------:|
| sed -i '50000,50010d' | range delete | 6.6 ms | 6.3–6.9 ms |
| hashline delete range | range delete | 52.6 ms | 51.4–55.1 ms |
| sed -i '50000a\\…' | insert after line | 6.7 ms | 6.6–6.8 ms |
| hashline insert | insert after anchor | 51.9 ms | 51.7–52.6 ms |

> Multi-line mutations are slower because hashline rewrites the file via atomic-rename
> for crash safety. Single-line `edit` uses an mmap fast-path and is competitive with sed.

### Safety features (no sed equivalent)

| Operation | Mean | Notes |
|-----------|-----:|-------|
| verify anchor before edit (100k) | 6.3 ms | Confirms content hasn't drifted |
| patch 10 ops atomic (100k) | 28.7 ms | All-or-nothing transaction |
| stale anchor rejection (100k) | ~9 ms | Fails fast with context + hint |

> sed silently applies edits even when the file has changed — no way to detect stale targets.
> hashline rejects the edit and shows exactly what changed, preventing silent corruption.
